## 分支说明

| 分支 | 作用 |
|------|------|
| `build` | **工作分支**，包含构建脚本、模板、手动规则。所有修改都在此分支进行 |
| `release` | 原项目发布分支（我们用 Pages 部署 build 分支，此分支可忽略） |
| `origin/build` | 原仓库残留的错误分支，可安全删除 |

## 目录结构（build 分支）

```
factory/
├── auto_build.sh          # 构建入口脚本
├── build_confs.py         # 核心：读取模板 + 规则 → 生成 .conf
├── ad.py                  # 拉取广告过滤列表 → resultant/ad.list
├── gfwlist.py             # 拉取 GFWList → resultant/gfw.list
├── manual_proxy.txt       # ★ 手动添加需要走代理的域名（所有配置共用）
├── manual_direct.txt      # ★ 手动添加需要直连的域名
├── manual_reject.txt      # ★ 手动添加需要屏蔽的广告域名
├── manual_proxy_plus.txt  # ★ _plus 配置专用：Apple/Microsoft 等强制代理域名
├── manual_gfwlist.txt     # 手动补充 GFWList 遗漏项
├── template/              # 各 .conf 的模板（使用 {{placeholder}} 引用规则）
│   ├── sr_head.txt        # 通用 [General] 头部
│   ├── sr_foot.txt        # 通用 [URL Rewrite] + [MITM] 尾部
│   ├── sr_cnip_ad.txt     # 国内外划分+去广告 模板
│   ├── sr_cnip_ad_plus.txt      # 国内外划分+去广告+Apple/Microsoft 模板
│   ├── sr_top500_banlist_ad.txt  # 黑名单+去广告 模板
│   └── ...
└── resultant/             # 构建中间产物（自动生成，无需手动修改）
```

## 修改方法

### 1. 切换到 build 分支

```bash
cd /home/xiangyao/code/github/Shadowrocket-ADBlock-Rules-Forever
git checkout build
```

### 2. 添加自定义代理规则

编辑 `factory/manual_proxy.txt`，在末尾追加即可。支持以下格式：

| 写法 | 自动转换为 | 示例 |
|------|-----------|------|
| 纯域名 | `DOMAIN-SUFFIX,域名,Proxy` | `tedcdn.com` |
| 子域名 | `DOMAIN-SUFFIX,子域名,Proxy` | `www-google-analytics.l.google.com` |
| IPv4 CIDR | `IP-CIDR,地址,Proxy` | `91.108.56.0/22` |
| IPv4 单地址 | `IP-CIDR,地址/32,Proxy` | `1.2.3.4` |
| IPv6 CIDR | `IP-CIDR,地址,Proxy` | `2001:b28:f23d::/48` |
| 不含 `.` 的关键字 | `DOMAIN-KEYWORD,关键字,Proxy` | `telegram` |
| `#` 开头 | 保留为注释 | `# Telegram` |

**示例（摘自 manual_proxy.txt 实际格式）：**

```
# 纯域名 → DOMAIN-SUFFIX,域名,Proxy
tedcdn.com
t.me

# 纯域名 → DOMAIN-SUFFIX,域名,Proxy（Apple Intelligence 相关）
apple.com
icloud.com
apple-relay.cloudflare.com
apple-relay.fastly-edge.com
cp4.cloudflare.com
mzstatic.com

# 子域名也是纯域名写法
www-google-analytics.l.google.com
pagead.google.com

# IPv4 CIDR → IP-CIDR,地址,Proxy
91.108.56.0/22
149.154.160.0/20
74.125.0.0/16

# IPv6 CIDR → IP-CIDR,地址,Proxy
2001:b28:f23d::/48
2a0a:f280::/32
```

> ⚠️ 注意：`apple.com` 加到 proxy 后，所有 Apple 子域名都走代理。
> 如果只想代理 AI 相关域名而不影响 App Store 等，应该写具体子域名而非顶级域名。

### 3. 添加直连 / 屏蔽规则

- 直连：编辑 `factory/manual_direct.txt`
- 广告屏蔽：编辑 `factory/manual_reject.txt`

格式与 `manual_proxy.txt` 完全一致。

### 3.1 修改 _plus 配置的强制代理域名

编辑 `factory/manual_proxy_plus.txt`，格式同上。此文件中的域名只会出现在 `_plus` 后缀的配置中，在 `GEOIP,CN` 之前匹配，确保即使有国内 CDN 也走代理。

当前内容：

```
# Apple Intelligence / iCloud Private Relay
apple.com
icloud.com
apple-relay.cloudflare.com
apple-relay.fastly-edge.com
cp4.cloudflare.com
mzstatic.com

# Microsoft 全球服务（避免国内 CDN 走直连）
microsoft.com
office.com
office365.com
live.com
outlook.com
msn.com
windows.com
microsoftonline.com
```

> 所有 `_plus` 模板通过 `{{manual_proxy_plus}}` 占位符引用此文件，修改一处即同步到全部 _plus 配置。

### 4. 创建全新配置文件（可选）

**步骤 1** — 新建模板 `factory/template/sr_my_custom.txt`：

```
#
# 我的自定义配置
#

# Apple 域名走代理
DOMAIN-SUFFIX,apple.com,Proxy
DOMAIN-SUFFIX,icloud.com,Proxy
DOMAIN-SUFFIX,apple-relay.cloudflare.com,Proxy
DOMAIN-SUFFIX,apple-relay.fastly-edge.com,Proxy
DOMAIN-SUFFIX,cp4.cloudflare.com,Proxy
DOMAIN-SUFFIX,mzstatic.com,Proxy

{{manual_proxy}}
{{manual_reject}}
{{ad}}

GEOIP,CN,DIRECT
FINAL,proxy
```

可用的占位符：`{{manual_proxy}}`、`{{manual_direct}}`、`{{manual_reject}}`、`{{manual_proxy_plus}}`、`{{ad}}`、`{{gfwlist}}`、`{{top500_proxy}}`、`{{top500_direct}}`

**步骤 2** — 编辑 `factory/build_confs.py`，在 `confs_names` 列表中添加：

```python
confs_names = [
    'sr_top500_banlist_ad',
    # ... 原有项 ...
    'sr_ad_only',
    'sr_my_custom',           # ← 新增
]
```

## 编译（本地测试）

```bash
cd /home/xiangyao/code/github/Shadowrocket-ADBlock-Rules-Forever

# 安装依赖
pip3 install -r requirements.txt
```

两种编译方式：

| 命令 | 说明 |
|------|------|
| `cd factory && python3 build_confs.py` | **仅编译模板**：用已有的中间文件生成 .conf，快速、不需联网 |
| `./factory/auto_build.sh` | **完整构建**：先联网拉取最新广告/GFW 规则，再编译模板，最后生成二维码 |

> 只改了模板或 `manual_*.txt` 文件时，用 `python3 build_confs.py` 就够了。
> 想同步上游最新广告/GFW 列表时，用 `./factory/auto_build.sh`。

构建完成后，根目录下的 `.conf` 文件即为最新生成的规则。

## 发布

### 自动发布（推荐）

```bash
git add .
git commit -m "Add Apple proxy rules"
git push origin build
```

push 到 `build` 分支后，GitHub Actions 自动触发构建并部署到 Pages。也可以在仓库 Actions 页面手动点 **Run workflow**。

**CI 触发条件：**
- `build` 分支 push（忽略 .md 和 LICENSE 变更）
- 每天 UTC 23:00（北京时间 8:00）定时构建
- 手动触发 `workflow_dispatch`

### CNAME 文件

确保 `build` 分支根目录有 `CNAME` 文件，内容为：

```
shadowrules.teches.top
```

否则每次 Actions 部署可能覆盖自定义域名设置。
